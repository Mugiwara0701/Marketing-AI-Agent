# Pipeline control API

A small REST service the dashboard backend calls to start and stop the agent. API reference for the dashboard
developer: [docs/pipeline-api.md](../docs/pipeline-api.md) (and `/docs` on the running service).

It does not run the agent and never contacts the office machine. It only reads and writes the `pipeline_control` row
in the agent's Supabase database (migration `supabase/migrations/0011_pipeline_control.sql`); the agent polls that row.
So it can be hosted anywhere that reaches Supabase: next to the dashboard backend, a VPS, Render, Railway, Fly...

## Settings (environment)

| Variable | |
|---|---|
| `DATABASE_URL` | required. The **limited** `pipeline_api` login from `python -m agent api-credentials` (Supabase pooler host) |
| `PIPELINE_API_TOKEN` | required. Long random secret; the dashboard backend sends it as `Authorization: Bearer ...` |
| `PIPELINE_API_CORS_ORIGINS` | optional, comma separated. Only if a browser calls the API directly |
| `PIPELINE_OFFLINE_AFTER_SECONDS` | optional, default 60. Heartbeat age after which the agent shows as offline |
| `PIPELINE_API_DOCS` | optional, default true. `false` hides `/docs` and `/openapi.json` |
| `PORT` | optional, default 8000. Set by Render and most hosts |

## Database login (once)

The API does not get the `postgres` password. Migration `0012_pipeline_api_role.sql` creates a `pipeline_api` role
that can only read `pipeline_control` and call `request_pipeline()` (no other table, no direct writes); Supabase's
`anon` / `authenticated` roles cannot call it at all. From the agent, with the admin `DATABASE_URL` in `.env`:

```bash
python -m agent migrate            # 0011 + 0012
python -m agent api-credentials    # new random password for pipeline_api; prints the DATABASE_URL for the API
```

Running `api-credentials` again rotates the password: update the host's `DATABASE_URL` afterwards.

## Deploy on Render

`render.yaml` (repo root) is a Render Blueprint: Render -> **New** -> **Blueprint** -> pick this repo and branch.
It creates the web service from `api/Dockerfile` (Singapore, closest to the Supabase region; health check
`/health`; redeploys only when `api/` or `render.yaml` change). Render then asks for:

- `DATABASE_URL`: the URL printed by `python -m agent api-credentials`. It must be the **pooler** host
  (`aws-0-<region>.pooler.supabase.com`): the direct `db.<ref>.supabase.co` host is IPv6-only, which Render cannot
  reach.
- `PIPELINE_API_CORS_ORIGINS`: leave empty unless a browser calls the API directly.

`PIPELINE_API_TOKEN` is generated by Render: copy it from the service's **Environment** tab to the dashboard backend,
together with the service URL (`https://<name>.onrender.com`). The free plan sleeps after 15 idle minutes (the next
request takes ~30-60 s); the `starter` plan stays up (`plan:` in `render.yaml`).

## Run

```bash
docker build -f api/Dockerfile -t pipeline-api .          # from the repo root
docker run -p 8000:8000 -e DATABASE_URL=... -e PIPELINE_API_TOKEN=... pipeline-api

# or without Docker
pip install -r api/requirements.txt
uvicorn api.app:app --host 0.0.0.0 --port 8000
```

Serve it over HTTPS (the host's TLS, or a reverse proxy in front): the token travels in a header.

## Tests

`pytest api` (from the repo root). `api/tests/test_postgres.py` runs the whole loop (API request -> agent applies it
-> API shows it) against a throwaway Postgres when `TEST_DATABASE_URL` is set.
